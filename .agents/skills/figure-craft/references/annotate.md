# Annotate —— 标注层（工程图 leader line）

代码：`src/components/ThingScene.tsx` 的 `AnnotationLabels`。
这一层是**产品机制**（"词找到物"）的一半，不是装饰，所以它比其它部分更值得较真：
图上任何一个字在动、在闪、压在形体上、或者消失，都会被读成"这站坏了"。

> 与 upstream 的差别（有意为之）：upstream 把 leader line / 标注气球列为**反例**
> （"blueprint furniture"），因为它的图靠形体自证。**我们相反**——引线是学习功能的载体。
> 但 upstream 对**线的纪律**照单全收：每根线要落在东西上、线宽屏幕恒定、文字归到图版四角。

## 1. 引线语法

真图纸的四点三段，别自创：

```
部件点(部件几何表面) → 出形点(包围盒朝外方向 × ANCHOR_EDGE_T) → 斜段肩点(× 外推档)
                                                              → 水平尾巴(+ LABEL_TAIL) → 文字
```

- **部件点落在几何表面上**（`dotFor`：逐块 mesh 取"朝外方向在主轴上那一面的中心"），
  不是数据里的 `position`——数据坐标常年和几何对不齐（tooth-brush 的 head 写在盒顶之上 0.06，
  归一放大 18× 后点浮在半空），点浮着就读不出"词找到了物件"。旋转过的部件（时钟指针）
  不能用世界 AABB 的支撑点替：斜包的角点会飘到形体外的空白里，逐块用自己的局部盒才对。
  没有几何的部件（只有数据）才退回 `position`，记得 `localToWorld`。
- 出形点从**几何边缘**出发（不是部件中心），所以引线看起来是"从实体上引出来的"。
- 尾巴**只走屏幕水平方向**，所以折角横平竖直，读起来像图纸。
- 文字用 DOM 渲染（drei `<Html>`）：能读设计字体令牌、能排两行（简单名 / 真名）。

## 2. 每帧的两遍结构

```
useFrame:
  ① 遍历部件 mesh → 每部件：包围盒中心 / 朝外法线 / 半径；顺手缓存每块 mesh 的世界 AABB
  ② 投影出 meshRects（硬占用）与 modelRect（软占用）
  ③ 建 ctxList（每部件：方向集 dirs、估算宽高、部件点世界坐标 `dotFor`）
  ④ 第一遍：选位（节流 LABEL_SOLVE_MS = 220ms，或优先级/部件数变化）
  ⑤ 第二遍：**每帧**用已定槽位重建引线几何 + 落笔（所以标签平滑跟随相机，决策不抖）
  ⑥ 复核：拿真实 DOM 矩形再查一次叠字（去抖 LABEL_HIDE_FRAMES = 4）
```

**④ 和 ⑤ 必须分开**。合在一起（每帧重算决策）会让两个标签为同一个坑位互相顶，
形成周期性横跳；只做④不做⑤，标签就会一格一格地跳着追相机。

## 3. 候选与打分

```
候选 = 2 锚点档 × 6 方向 × 10 外推档
方向 = [朝外, 反向, 屏幕右, 屏幕左, 屏幕上, 屏幕下]   DIR_COST = [0,4,2,2,3,3]
外推 = LABEL_REACH_CANDIDATES = [0.95 … 6.6] 世界单位
成本 = 落在模型整体包围盒外(COST_OUTSIDE_BODY = 40)
     + DIR_COST[方向] + 外推档×2 + 锚点档(0.5)
```

按部件优先级（激活 > 悬停 > 常态）依次占位，**同级顺序必须是固定的部件序号**。

- ❌ 用"枚举序里第一个合格"取槽：远的那档恰好排在前面时，标签会被拉到很远。
- ❌ 同级按"近相机优先"排：相机动一点顺序就换人，同一个坑位换来换去 = 视觉上的闪。
- ❌ 只给"朝外"一个方向：贴边的部件（反应堆最右侧的涡轮）28 个候选位全部落空，**标签直接消失**。

## 4. 占用：硬的是 mesh，软的是整体

| | 是什么 | 违反的后果 |
|---|---|---|
| **硬占用** `meshRects` | 每块 mesh 自己的屏幕矩形（并集 ≈ 剪影），外扩 `MESH_PAD = 4px` | 判失败，换位置 |
| **软占用** `modelRect` | 整个模型的屏幕包围盒 | 只加 40 的成本，**允许但不优先** |

**为什么硬占用必须逐 mesh**：早先用"整个模型的包围盒"当硬占用，那个矩形就吃掉了
画布 694px 里的 x103–647 —— 所有候选位全员失败，全部标注一起退化成"压在图上 + 淡排"，
看起来就是"标注糊在图上"。逐 mesh 判定才有解：穹顶上方、塔体左右这些真空区都能落字。

退让顺序（三级），**每一级都不许叠字**：

```
不压形体 + 不压已放置标签   → 实排 opacity 1
（无解）不压标签，可压形体   → 淡排 opacity 0.35
（再无解）                  → 不画（引线也要一起隐藏，不留浮线）
```

## 5. ★ 三个浮点噪声坑（"字在闪"的真凶）

这三条都是**同一类错误的三个变体：把逐帧重算的结果用在"二值判断"上。**
只要判断依据是一个可能在 0 附近抖动的浮点数，符号就会翻转，视觉上就是跳。

### 坑 1 —— 文字朝向不能用现场算的符号

```js
// ❌ 部件朝外方向与相机右轴近乎垂直时 sx ≈ ±1e-9，符号逐帧翻转
into.label.addScaledVector(tmp.right, (sx >= 0 ? 1 : -1) * LABEL_TAIL)
const left = sx >= 0 ? s.x : s.x - estWidth

// ✅ 朝向由槽位里的 textRight 决定（选位时算一次 + 粘滞）
into.label.addScaledVector(tmp.right, (slot.textRight ? 1 : -1) * LABEL_TAIL)
```

后果量级：`translateY(-50%)` 与 `translate(-100%,-50%)` 相差**一整个标签宽度**
（实测 139px）。实测抓到的证据是同一个槽位、同一组几何参数下，
DOM 的 transform 在 `matrix(1,0,0,1,0,-11.875)` 与 `matrix(1,0,0,1,-138.609,-11.875)` 之间跳。

**死区**：`TEXT_SIDE_DEADBAND = 0.15`，判据依次是「方向的水平分量」→「朝外方向的水平分量」
→ 两者都在死区就**按固定约定朝右**。最后那一步千万别写成 `hv >= 0`，那是把坑换个地方复现。

### 坑 2 —— 方向向量必须逐部件取

```js
// ❌ tmp.normal / tmp.vis 是构建循环留下的"最后一个部件"的值
into.edge.copy(entry.center).addScaledVector(tmp.normal, radius * t)
// ✅ 挂到 ctx 上
into.edge.copy(ctx.entry.center).addScaledVector(ctx.normal, ctx.radius * t)
```

症状：除末位以外所有标注都按**错误的朝外方向**外推，落点漂移、位置看着"没道理"。

### 坑 3 —— 改了槽位就必须重算 rect 再校验

粘滞复用上一轮的坑位时会同步上一轮的 `textRight`。**改完必须用新槽位重算 `rect`**
再跑 `clearOfLabels`——否则"校验的矩形"和"落笔的矩形"差一个标签宽度，
会和前一个已经占位的标签叠字（实测：`STEAM MAKER` 正好印在 `HOT PART` 上）。

## 6. drei `<Html>` 的 portal 陷阱

`<Html>` 渲染进 **DOM portal**，**不受父 group `visible` 控制**。
"隐藏标签"必须直接切 DOM：

```js
const showLabel = el => { if (el.style.display === 'none') el.style.display = '' }
const hideLabel = el => { if (el.style.display !== 'none') el.style.display = 'none' }
```

`display` 只在**变化时**写（不要每帧无脑赋值，会触发无谓的样式/布局抖动）。

## 7. 自检口径

标注的毛病**静态看不出来**，必须逐帧采样（见 `verify.md`）：

```bash
node .agents/skills/figure-craft/scripts/figure.mjs labels clock
```

判据是**相邻采样之间的跳变（jump）**，不是位移总量：相机自转会让标签平滑漂移
（1–2px/次采样，正常），而抖动是一步跳一整个标签宽度。
另外要覆盖**激活态**（点文中部件词 → 优先级重排，最容易触发重排抖动）：
`labels` 与 `eval` 配合，点完再看一遍，此时只允许**透明度**变化，位置必须 0 跳变。
