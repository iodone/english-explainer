# Craft —— 怎么把图从"能看"画到"经得起放大"

本文是 `DESIGN.md` §1.5 的可执行长版。§1.5 定的是**契约**（用什么材质、什么角色、
什么颜色），这里写**手艺**（画到什么密度、细节从哪来、哪里最容易被退回）。

## 1. "精细"到底是什么

upstream 的一句判断标准，直接搬过来用：

> **1× 看是一台清楚的机器，4× 看每个区域都还有真东西可找。**
> 光秃秃的一面、空着的一角，是**没做完**，不是"干净"。

本项目还要多一条：**精细度来自零件密度，不是多边形数**。给圆柱加 `segments=64` 不会让图变好，
在筒身上加三道箍带、在法兰上加一圈螺栓、在箱面上加分缝——才会。

反面（upstream 被退回最多的四种，本项目同样适用）：

| 反例 | 表现 | 改法 |
|---|---|---|
| 抽象堆叠 | 浮板/薄片象征"层" | 变成真的机构：抽屉、塔节、管束、检修门 |
| 一块大平板 | 一个大面加几根线 | 拆成底座 + 台面 + 分缝 + 螺栓圈 + 铭牌 |
| 噪声细节 | 满屏随便撒的点/线 | 每个细节属于某个零件，并且**落在边界上** |
| 纹样中途截止 | 刻度/箍带/分缝半路齐刷刷断掉 | 走满整条边，或者渐隐（`opacity` 拉长过渡带） |

## 2. 明暗与墨线（已经写进材质，改的时候别破坏）

`PAPER_TONES`（`paperSurface.ts`）每件一套四色：**顶面 / 侧面亮 / 侧面暗 / 排线墨**，
外加一套 `lit{base,dark,top}` 激活档。

| finish | 侧面亮 | 侧面暗 | 顶面 | 语义 |
|---|---|---|---|---|
| `hull` | `#EDE7D8` | `#B9AE93` | `#F7F3E8` | 外壳 / 包裹 |
| `cold` | `#F4EFE3` | `#C7BDA5` | `#FBF8F0` | 结构件、舱段（默认） |
| `titanium` | `#FCFAF4` | `#D8D0BD` | `#FFFFFF` | 最亮，主体件 |
| `warning` | `#E9A79E` | `#C0605A` | `#F2BDB5` | 功能指示位（每件 ≤ 2） |
| `shell` | `#F2EDE1` | `#C3B9A2` | `#FAF7EF` | 透明壳，**alpha 0.22**，内部透出来（激活时 0.48） |

四条纪律：

1. **顶面独立档**：`smoothstep(0.62, 0.72, n.y)` 选 `uTop`。这是等距读法能读成实体的关键——
   **任何新几何都不要绕开这一档**（绕开了，朝上的面会和侧面同色，图立刻变平）。
2. **点亮 = 加重上墨，不是提亮**（2026-10-15 修，旧版反之）。每档那套 `lit{base,dark,top}`
   是**更深**的一档，激活时同时排线提前（`0.30/0.54` 各减 `inkBoost = 0.05 × emphasis`）
   + 排线加重（混合 `0.34 + 0.08 × emphasis`）。**纸面不吃 accent**：身份色只走
   线/点/标注，面色只按 finish 的纸阶走（像纸上的彩铅，不是给面上塑料漆）。

   > **为什么必须反过来**：纸底是亮的（`#F4F1EA`）。往亮走 = 对比度**下降**，
   > 读出来不是"被照亮"而是"褪色/变灰"——旧 lit 档是近白色（`#FBF7EC`/`#FFFDF6`），
   > 被点中的部件面均亮度实测 208→220，用户的原话是"我点击图像的部位，都变灰了"。
   > 制图语境里"聚焦"只有一种表达：**墨更实、线更粗**。同样的道理，
   > 压暗（`uDim`）只能"向纸面退开"（降不透明度），不能"加深颜色"。
2c. **红件被点亮时保持自己的红**（`markInk`）。`warning` 是**语义色**（功能/警示位，每件 ≤ 2），
   不是装饰：被点亮的红件只"更实更粗"（线宽 2.5、排线加密、点阵 1.5×，纸面**不换档**），
   **不换成 thing 的身份色**——否则"这个部件是热的/带电的"这层意思凭空消失
   （用户实测：点测电表的红线圈，红变土黄）。accent 只给纸面灰阶的三档上色：
   它们本来无彩，正需要 accent 给色相。标注层同规则（`markFor(finish)`）。
2b. **accent 用于纸面必须先蘸墨**：`thing.color` 是**浅粉彩身份色**（`#87CEEB` /
   `#E0FFFF` / `#FFFACD`…），直接当线色画等于没有线（对纸对比度 1.05–1.5:1，
   实渲染像素 `(140,195,210)` —— 用户看到的"变灰"有一半是它）。
   画线/点阵/标注一律过 `accentInkOf()`（`paperSurface.ts`）：保色相、压到相对亮度
   **Y ≤ 0.2**（≈3.7:1，各色相等重）。**纸面不吃 accent**：面色只走 finish 的纸阶，
   身份色只留给线/点/标注。否则灰阶件一选中就洗上一层淡红，读起来像第二个 warning 件。
   **唯一的例外是黄色相（40°–70°）：它在纸面上无解，直接换档到激活红 `#E8453C`。**
   sRGB 里低明度的黄只能往橄榄/棕走：金 accent 压深是 `#8f7800` 橄榄土黄、压到 Y 0.28
   是 `#a88e00` 深黄，换青墨又变成另一种身份（用户三次否决："黄""还是黄的""蓝绿色的"）。
   色相身份保不住就别保了——金色件改用"红笔圈出"的读法（≈3.5:1，线宽 2.5 撑得住），
   这也正好是 DESIGN §1 里"红仅作部件激活与警示点缀"那一条。
   面色不跟随这支红（`makePaperMaterial` 不再接收 accent）——选中金色件时只有线/点/标注变红。
   同理：`thing.color` 原色**任何地方都不要直接画在纸面上**。
   这就是文中部件词 `--color-word-part`（hud 青加深 60%）在 3D 侧的同一套做法。

   > **坑（踩过）**：不要用 `THREE.Color.getHSL/setHSL` 做这个换算。
   > 三 r185 的默认 `colorSpace` 是 `workingColorSpace`（**线性** sRGB），
   > `l = 0.42` 被当成线性值，出来是 0.68 的浅蓝——改了等于没改。
   > sRGB ↔ HSL 手算（`hexToHsl` / `hslToHex`），或者换算完自己验一遍对比度。
3. **线宽屏幕恒定**：`HULL_WIDTH_PX = 1.1` CSS px，每帧按「世界单位/像素」换算。
   写死 `lineWidth={2}` 在缩放后会露馅。
4. **屏幕空间交叉排线**：暗部自动长出淡墨斜线（阈值 `0.30 / 0.54`，混合 `0.34`）。
   排线阈值已被 `hatchBias` 按档偏移过（`warning` +0.12 更密、`titanium` −0.04 更疏），
   加新档时沿用这个思路，别直接改全局数值。

**激活态的三条通道**（改高亮相关代码前先分清，`usePartHighlight`）：

| 通道 | 谁在用 | 面 | 线 |
|---|---|---|---|
| `activePartIds` | flow 当前步 | `lit` 档 + 排线加重（`uEmphasis 1`） | accent 墨色 + 2.5px |
| `pastPartIds` | flow 已过步 | `uDim 0.6` | opacity 0.45 · 0.9px |
| `dimOthers` | flow 未到步 | `uDim 1` | opacity 0.12 |
| `highlightPartId` | 阅读态点选 / practice 悬停 | `lit` 档 + 排线加重 | accent 墨色 + 2.5px |
| `highlightPartId` 之外 | 阅读态点选时的**其余部件** | `uDim 0.55` | opacity ×0.4 · 0.9px |

> `warning` 是唯一例外：它的 `lit` 档与常态同值，面只在排线上加重；线色也保持
> `#E8453C`，不换 accent。这样"选中前后同一个红件必须还是同一支红"。

> 最后两行成对出现才成立：**只降面不降线**会留下一圈硬墨边的"鬼影"（淡面 + 实线），
> 比不退还乱——这是 2026-10-15 之前的表现。标注层同理：`focus` 时其余标签 0.45、
> 引线 0.22、点阵 0.35，被点中的那个 1 / 0.9 / 1。

**两层表达的职责分工**（别混）：`hull` / `titanium` / `shell` 走 **BackSide 反向外壳描边**
（连续剪影边，把体量读出来）；结构件只走 **Edges 纵线**（低多边形结构感）。
再加一层就会糊。

## 3. 细节原语配方（`primitives.tsx`）

**参与高亮**的原语（带 `partId`，走 `SketchMesh`）：
`SketchMesh` · `Rod` · `BoltCircle` · `SeamRing` · `TickRing` · `Gear`

**纯草稿线**（不参与高亮，永远是被动墨线）：
`DraftLine` · `DraftSegments` · `PanelLines`

> `PanelLines` / `DraftSegments` 不参与高亮是**有意**的：分缝、刻度是"纸上的墨"，
> 不是零件的部位。需要点击/点亮的那根"线"必须用 `Rod`（细圆柱 mesh）。
> **drei `Line` 永远不参与高亮**——这是本项目最容易踩的坑之一。

| 形体 | 必备细节 | 用哪个 |
|---|---|---|
| 筒身 / 压力容器 / 管道 | 2–3 道箍带，沿轴向大致等分 | `SeamRing` |
| 法兰 / 盖板 / 轴承座 | 一圈螺栓（6–12 颗） | `BoltCircle` |
| 表盘 / 刻度环 / 旋钮 | 长短刻度交替（`longEvery` 每 5 或 3 一根长） | `TickRing` |
| 传动 | **真齿形**，啮合中心距 = r₁ + r₂ | `Gear` |
| 箱体大平面 | 分缝把大面切块（每块别超过 ~1.5 世界单位宽） | `PanelLines` |
| 长杆 / 拉杆 | 节点环 + 端头（别让一根光杆裸奔） | `SeamRing` + `BoltCircle` |
| 底座 | 分缝 + 四角螺栓 + 铭牌位 | `PanelLines` + `BoltCircle` |
| 装饰性纹理带 | 一批淡墨线段，一次绘制 | `DraftSegments` |

**细节要落在边界上**：`TickRing` 贴在盘面边缘、`SeamRing` 箍在筒身上、分缝走到箱体棱边。
放在半空中的刻度、离边缘 2 个单位的箍带，读起来都是"贴上去的贴纸"。

## 4. 体量与落地

- **每个部件要坐在别的部件上**。悬空的零件读成装饰。改比例时优先检查这个。
- **厚度**：别用零厚度平面；看不出厚度的部件在大角度旋转时会消失。
- **落地阴影**：`ContactShadows` 每帧贴模型底面、按足印给 `scale/far`
  （`GroundShadow`）。**不可缩放外层 group**——它的正交视锥会跟着放大，
  整块阴影糊成一块灰板。这是已经付过学费的坑。
- **透明壳**（`finish: 'shell'`）：安全壳 / 玻璃罩 / 护罩用它，内部机构透出来。
  用不透明材质包住内部 = 把这张图的信息量砍掉一半。
- **空腔件（盆 / 锅 / 桶 / 杯 / 管）必须双面渲染**：纸面材质是 `side: DoubleSide` +
  片元里 `if (!gl_FrontFacing) n = -n;`（法线翻过来，明暗与顶面档才对得上）。
  单面渲染时凹面全是背面被剔掉，**往盆里看就是一个黑洞**——其实是透到地面影子上去了。
  所以盆只要给外壳（外皮）就够，内壁自动可见；内壁想有颜色才另加一件（如勺子的"深的那一层"）。

## 5. 取景与构图

- 取景全在 `ModelSpanProbe`（`ThingScene`）里，**调 `FIT_MARGIN` 别调相机**，
  它比默认松（1.28），是给标注层留的余地。**别改回 drei `Bounds` 的 `fit()`**：
  `fit()` 只写 goal，而 `Bounds` 自己的 `refresh()` 会把 goal 清空（`size/controls` 一变就发生），
  取景会在加载期随机丢失 —— 相机停在初始机位、模型缩成画面中间一个小点。它量的是**部件盒**（`partsBounds`：带 `name` 的
  mesh），**不是整组**——几何里的草稿线/地面线是装饰，作者给它们写多长全凭手感
  （power-socket 的墙线是插座本体的 10×，345 件里 69 件装饰跨度 > 2× 部件跨度）。
  拿整组取景，这些图里的物件就是画面上一个小点。装饰线超出画布是正常的（草稿线就该出画布）。
- 模型占画布约 55–65%。四角有图版件（SPECIMEN / MODEL / 操作提示 / 读数），
  别让形体压到它们。
- 分栏可拖动 → 画布 resize → 取景组件的 `useThree(s => s.size)` 依赖会重跑，自动重取景。**改动几何后一定要在窄画布下再看一眼**
  （标注层的可用空间会跟着缩，见 `annotate.md`）。
- **跨度归一（先量再画）**：标注点半径、引线外推档、`Rod`/`SeamRing` 默认半径都是**世界单位的绝对
  尺寸**，整套按"模型跨度 ≈ 2"调的。新写一件几何前先量一下部件的 `position` 跨度：
  **小于 2 就是小世界**，同一套绝对尺寸会立刻露馅——标注点直径占到形体的三成、相邻点粘成一串黑球、
  标签被外推档甩出画布。`ThingScene` 现在会自动把跨度 < `MODEL_SPAN = 2.2` 的模型放大到基准
  （只放大不缩小），所以不必再改几何坐标；但**改了取景/缩放相关代码就要连着改这边**：
  归一与取景都是 `ModelSpanProbe` 在帧循环里**命令式**写完的（量部件盒 → 写
  `modelGroupRef.current.scale` → 摆机位 + `near/far` + `controls.maxDistance`），
  没有中间 state、也不经过 drei `Bounds`；改完记得窄画布 + 宽画布各看一眼。
  量跨度的老办法：`things.map(t => Math.max(...t.parts.map(p => p.position[0])))` 之流，
  拿分位数看整体（当前 p50 = 0.46）。
- 相机默认透视 `[5, 3, 5] fov 50`，可切正交（工程图观看方式）。
  `autoRotate autoRotateSpeed={0.4}` ≈ 150 s 一圈——慢到不干扰阅读，
  但**标注层必须在旋转全程都成立**，这是自检的一部分。

## 6. 加新几何的操作顺序

1. `src/data/types.ts` 改类型（**先改类型再写数据**）
2. `src/data/things/<slug>.ts` 写 parts + article + flow + keyExpressions
3. `src/data/dict/<slug>.ts` 写词条（key 用动词原形）
4. `src/geometry/<slug>.tsx` 写几何：每个部件一个 `SketchMesh`/`Rod`，带 `name={partId}`
5. `src/geometry/index.ts` 的 `GEOMETRY` map 注册一行
6. `npx tsx scripts/validate-data.mjs` —— 部件↔词闭环比什么都先跑

**部件 id 一旦写进文章就别改**：改 id = 改数据 + 改几何 + 改 flow，最容易漏的是 flow 的
`sentenceRef`（那是**全篇连续**句索引，跨段累加、0-based，写的时候数清楚）。
